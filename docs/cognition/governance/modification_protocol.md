# ④ 修改协议（Modification Protocol）

> 让豆包/Agent 在**已知代码**上改的契约。铁律：**无依据不改核心层**。
> 对应方法论：**"真正的策略是让 Codex 在已知代码上改"** —— 依据链就是"已知"的证明。

## 核心铁律

1. **无依据不改核心层** —— 任何对核心层代码（paper_trader / retro_loop / error_log /
   quant_ersibang 等已知度 ≥4.5 的组件）的改动，必须能追溯到：
   - 某条 **error_log**（错误日志四问法记录）
   - 某个 **回测结果**（quant_backtest / esb 报告）
   - 某条 **周复盘改进项**（retro_loop IMP-xxx）
   - 或**你（人）的明确指示**
   ❌ 禁止"我觉得这样更好"的无依据改动。

2. **改动必须小步 + 回测对比** —— 改前跑一次基线，改后跑一次对比（同数据同区间），
   把"改前 vs 改后"写进认知卡修改历史。

3. **改完必须闭环** —— 相应 error_log 状态更新（fixed/verified），认知卡"已知缺陷"节同步。

4. **实验层自由，核心层受限** —— 实验层（quant_multifactor 等未验证代码）可以自由迭代研究，
   但**不进实盘/虚拟盘买入**；核心层任何改动需走本协议。

## 豆包（Agent）改动流程

```
① 读认知卡（对应策略卡 + knowledge_map 层级状态）
② 说明改动依据（error_log / 回测 / IMP / 你指示）→ 写入请求
③ 你确认（审批流 / 直接指示）
④ 小步改（diff 最小化，不动无关代码）
⑤ 回测对比（同数据基线 vs 改动后）→ 附结果
⑥ 更新认知卡（修改历史 + 缺陷状态）
⑦ git commit（message 带依据链）
⑧ 云上部署 + 验证（互审 / 真实验证）
```

## 依据链书写模板（git commit / 改动说明必含）

```
改动：<一句话>
依据：<error_log EL-xxx / 回测报告 xxx / IMP-xxx / 用户指示>
验证：<基线 参数 → 改动后 参数，同数据 区间>
```

示例（真实发生）：
```
改动：paper_trader 单一日历源 _mkt_date
依据：error_log EL-2026-10-18-010/011/012（系统数据层，日期倒挂）
验证：修复前倒挂 3 条 → 修复后 0 条，last_market_date=2026-10-16
```

## 禁止清单

- ❌ 不读认知卡直接改核心层
- ❌ 修改参数/阈值而无来源（如把 RSI<45 改成 50 却不附任何回测证据）
- ❌ 删除历史数据或清空日志（error_log/improvements 是进化证据，只追加不删）
- ❌ 用 mock/演示数据冒充真实验证结果
- ❌ 实验层代码未过晋升门就写进虚拟盘/实盘买入路径
- ❌ 绕过你直接拍板（humans at the edge）

## 违反后果（自查）

- 发现违反 → 立即停止改动，说明依据缺口，等你指示
- error_log 会把"无依据改动"作为系统层教训记录（四问法：下次怎么做 = 先补依据链）

## 生效范围

本协议对以下代码库所有改动生效（ANENGOS 仓库 + 云上 /opt/anengos）：
- connectors/ 全部核心件
- cron/ 定时脚本
- app.py / 审批路由
- docs/cognition/ 认知体系本身（改认知卡状态需你确认）
