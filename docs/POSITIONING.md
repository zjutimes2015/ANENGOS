# ANENGOS 产品定位收敛：企业私有知识库问答 SaaS

> 借鉴清单第 6 步（最后一步）。本文是产品收敛的"宪法"：所有能力围绕一个场景组织，
> 新增功能必须能回答"它如何让客户更好地问自己的知识库"，否则不做或降级为插件。

## 1. 一句话定位

**让企业把资料交给 ANENGOS，然后用 Claude / Cursor / API / 网页四种方式，向 AI 提问自己的知识库。**

- 客户：中小企业的运营/客服/销售/法务团队，资料散在文档里、新人上手慢、重复回答消耗人力。
- 价值主张：**上传资料 → 5 分钟接入 → AI 用你公司的资料回答你公司的问题**，按用量付费，数据租户隔离。
- 一句话拒绝："ANENGOS 不做通用 AI 操作系统，做企业私有知识库问答 SaaS。"

## 2. 目标客户与核心场景

| 客户画像 | 典型场景 | 核心动作 |
|---|---|---|
| 客服团队 | 产品手册/售后 FAQ 太多，客服答错或查不到 | 上传手册 → 客服在网页/Claude 里问 |
| 销售团队 | 报价、合同模板、案例库散落各处 | 上传资料 → 销售问"这个客户该报什么价" |
| 运营/内容团队 | 品牌资料、活动 SOP、历史方案 | 上传资料 → 新员工直接问"上次活动怎么做的" |
| 法务/合规（后期） | 合同、制度、政策文件 | 上传资料 → 合规问答 + 来源可溯 |

**一个决策原则**：客户要的是"回答"，不是"工作流"。总装线/互审/审批是**支撑能力**（保证 AI 可信），不是卖点本身。

## 3. 能力分层（收敛后的架构视图）

| 层 | 能力 | 状态 |
|---|---|---|
| **核心层（客户直接感知）** | 知识库上传/检索/问答（RAG）；租户知识库 API；客户站门户（登录 + 问答 UI）；MCP 端点（Claude/Cursor 直连） | 已上线 |
| **商业层（收费依据）** | 信用额度池（套餐月度分 + 按量包）；租户配额/账单/CSV/Webhook 告警；自助开通；一行安装（/install）；llms.txt 分发 | 已上线 |
| **可信层（AI 可靠的前提）** | 任务队列 Failover（断点续跑/失败重放）；审批门禁 + 审计追踪；多智能体适配器（统一 Schema） | 已上线（支撑用途） |
| **边界层（明确不做）** | 通用 AI 操作系统/浏览器内核；账号池/养号（合规风险，不抄 AgentKey）；模型转售（BYOK，客户自带模型 key）；低代码工作流平台 | 不做 |

## 4. 与 AgentKey 的生态位（不竞争，上下游）

- AgentKey：**接入层**——一把 key 调 1800 个公开工具（搜索/爬虫/社媒），解决"AI 没有手"。
- ANENGOS：**组织层**——企业私有数据 + 可信问答，解决"AI 没有企业记忆"。
- 互补关系：客户可以同时用 AgentKey 拿公开数据 + ANENGOS 问私有资料。

## 6. GTM（获客 → 接入 → 付费）

1. **发现**：`/llms.txt`（AI 可读产品说明，让 agent 发现平台）
2. **开通**：主页 → /signup 自助开通，拿租户 token
3. **接入**：`/install` 一行安装（Claude Code/Cursor 现成配置 + curl 验证），5 分钟闭环
4. **验证**：MCP 冒烟 → 客户站问答 → 信用池扣费可见
5. **付费**：网页下单 → 收银台 → 官方支付（备案后）→ 配额/信用分到账
